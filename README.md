# Учебный чат-бот поддержки

## Описание

Прототип вымышленного интернет-магазина демонстрирует Increment лабораторных работ 3 и 4 по управлению проектами с Scrum. Интерфейс и содержание представлены на русском языке; заказы, ответы и график оператора придуманы для учебной демонстрации. Для свободных текстовых вопросов приложение сначала применяет существующие правила, а при отсутствии совпадения может попросить локальную модель выбрать подходящий FAQ.

## Запуск

Для режима с локальной моделью сначала запустите Ollama и убедитесь, что в локальном списке есть `qwen3:8b-q4_K_M`. Модель не загружается автоматически, и к облачным сервисам приложение не обращается. Из корня проекта запустите Node.js сервер:

```powershell
node server.js
```

Откройте `http://127.0.0.1:8000/`. Node.js 18 или новее нужен для встроенного `fetch`; внешние npm-зависимости не требуются. Сервер слушает только `127.0.0.1`; тайм-аут запроса к Ollama по умолчанию 60 секунд и настраивается переменной `OLLAMA_TIMEOUT_MS`, например:

```powershell
$env:OLLAMA_TIMEOUT_MS = "90000"
node server.js
```

Для прежнего режима без ИИ откройте `index.html` напрямую (`file://`) или подайте статические файлы другим локальным сервером. В этом режиме все прежние кнопки и правила работают, запросы к ИИ не выполняются, а нераспознанный текст получает стандартную подсказку. Для проверки локальной персистентности используйте один и тот же браузер и origin. Остановите Node-сервер сочетанием Ctrl+C.

## Возможности Increment

- Меню, категории «Оплата», «Доставка», «Аккаунт», FAQ по кнопкам и распознавание русских ключевых слов.
- Для свободного текста правила/команды и распознавание номера заказа выполняются первыми. Только если они не нашли ответ, режим Node отправляет в Ollama текущую фразу и список ID/вопросов FAQ без истории переписки.
- Ollama возвращает только JSON с `faqId` либо `null`. Сервер и интерфейс проверяют ID; пользователю показывается точный текст выбранного FAQ, а не сгенерированный ответ. Источники отмечаются «По правилам» и «Подбор с помощью ИИ».
- Неоднозначный, не относящийся к FAQ, недоступный или слишком медленный ответ модели приводит к прежней подсказке. Ожидание обозначается по-русски; «Начать заново» отменяет незавершённые запросы.
- «Главное меню» не стирает историю, а «Начать заново» является отдельным действием.
- Заказы 1001 и 1002, некорректный формат номера и корректный, но отсутствующий номер различаются. Все сведения об учебных заказах вымышлены.
- Оператор, его график и проверяемые контрольные часы — демонстрация; реальное обращение не отправляется и реальный оператор не подключается.
- Голос «Да» или «Нет» сохраняется один раз для каждого ответа; к нему можно сохранить необязательный комментарий длиной до 240 символов.
- После перезагрузки локально восстанавливаются история разговора, правки существующих ответов FAQ и оценки. Они хранятся раздельно в `localStorage` этого браузера; кнопка в «Демо-панели» удаляет все три набора данных.
- Открытая «Демо-панель» явно обозначена как учебная и не имеет реальной аутентификации. В ней доступны редактор FAQ, расписание Europe/Moscow и локальная статистика, не являющаяся глобальной.

Нет базы данных, реальных аккаунтов, оплаты, клиентских данных или реального оператора. Ollama работает локально; история не отправляется модели и пользовательский текст отображается как текст. Выбор FAQ не гарантирует правильную классификацию: при сомнении модель должна вернуть `null`, иначе используется стандартная подсказка.

## Дополненные критерии приёмки US-03

- **Дано:** введённый вопрос совпадает с существующими правилами FAQ.
- **Когда:** покупатель вводит «Какие способы оплаты доступны?».
- **Тогда:** чат показывает текущий ответ FAQ с пометкой «По правилам» без обращения к `/api/faq-match`.

- **Дано:** свободный запрос не распознан существующими командами, заказами или регулярными выражениями; прототип запущен через `node server.js`, а локальная Ollama доступна.
- **Когда:** покупатель вводит перефразированный вопрос, соответствующий одному вопросу FAQ.
- **Тогда:** локальная модель получает только текущую фразу и каталог FAQ с ID и вопросами, возвращает структурированный `faqId`, а чат показывает точный сохранённый ответ FAQ с пометкой «Подбор с помощью ИИ». История не передаётся модели.

- **Дано:** пользователь ввёл запрос вне каталога, модель недоступна, ответ не прошёл проверку или истёк тайм-аут.
- **Когда:** приложение завершает попытку выбора FAQ.
- **Тогда:** чат показывает существующую подсказку с выбором темы и запросом оператора, не показывает сгенерированный текст и не блокирует дальнейшее взаимодействие.

- **Дано:** запрос свободного текста уже ожидает ответ модели.
- **Когда:** покупатель нажимает «Начать заново».
- **Тогда:** незавершённый запрос отменяется или его результат игнорируется; в новой беседе не появляется поздний ответ.

- **Дано:** интерфейс открыт через `file://`.
- **Когда:** введён текст, не совпавший с командами и правилами.
- **Тогда:** запрос к ИИ не выполняется и показывается прежняя подсказка.

### Свидетельства демонстрации US-03

При повторной проверке через `http://127.0.0.1:8000/` с запущенной Ollama и установленной моделью `qwen3:8b-q4_K_M` чат очищался между сценариями. Для первого сценария сетевой запрос к `/api/faq-match` отсутствовал; второй и третий запросы выполнены через локальный сервер. Скриншоты сняты с реального браузера.

### Ручная проверка `file://`

Автоматическая браузерная проверка остаётся **непроверенной**: встроенный браузер VS Code отклонил файл как находящийся вне доверенной папки. Для ручной проверки откройте `index.html` двойным щелчком в обычном браузере и убедитесь, что адрес начинается с `file:///`. Откройте инструменты разработчика (F12), вкладку Network и включите сохранение запросов. Введите «Какие способы оплаты доступны?» — ожидается ответ об оплате банковской картой с пометкой «По правилам». Затем введите «Можно ли вернуть товар через месяц?» — ожидается «Пока нет подходящего ответа. Выберите тему, укажите номер учебного заказа или запросите оператора.». В списке Network не должно быть запросов к `/api/faq-match`.

## Моделирование командной работы

Работа представлена индивидуально. Carlos Tarazona — реальный автор работы и Product Owner. Участник А (Scrum Master) и Участник Б (разработчик) — вымышленные участники учебной модели. Участие вымышленных членов команды и проведение событий Scrum являются образовательной симуляцией, разрешённой преподавателем.

| Роль | Симулируемые обязанности |
|---|---|
| Product Owner | Требования, приоритеты и критерии приёмки |
| Scrum Master | Планирование встреч и отслеживание препятствий |
| Разработчик | Интерфейс, логика чат-бота и тестирование |

Указание вымышленных ролей описывает распределение ответственности в учебной симуляции. Оно не означает, что вымышленные участники реально выполняли работу, создавали коммиты или проводили тесты.
